## 1. Executive Summary

This forensic audit was commissioned to independently verify the veracity, methodology, and integration status of all AI/ML/DL/GenAI claims made in the CA Career OS platform. 

### Key Findings Summary
1. **Notebook Execution Authenticity (`PASS`):** All four research notebooks (`01` through `04`) exist, contain genuine execution counts and real execution outputs (not fabricated text), and were successfully reproduced top-to-bottom in an isolated clean sandbox without runtime errors.
2. **Dataset Provenance (`PARTIAL`):** Datasets were **not downloaded from external live web APIs or scrapers**. They were synthesized by deterministic Python generators in `scripts/data_generators/`. While structurally authentic and representative of CA terminology, they are synthetic domain fixtures rather than real-world hiring outcomes.
3. **Metric Quality & Data Leakage (`FAIL` on Real-World Claims / `PASS` on Synthetic Benchmark):**
   - The reported Random Forest score ($MAE = 0.030, R^2 = 0.9999$) is mathematically valid **only because the target label was generated by a noise-free piecewise deterministic rule on the exact same 6 input features**. The model simply learned the synthetic code logic.
   - In Job Fraud Risk Detection, 15 scam postings and 15 review postings were created by repeating 3 templates 5 times. Cross-validation suffered from template leakage across train/test splits.
4. **Model-to-Product Integration (`PARTIAL` - Pragmatic Transpilation):**
   - **The NestJS backend does NOT load `.pkl` model binaries.**
   - Instead, the data science findings were **transpiled into native TypeScript**: the fraud detector implements the exact logistic regression equation with fitted coefficients and intercept (`-0.8957`); the deduplication engine implements token n-gram cosine similarity; and the match engine uses empirical feature weights (45% mandatory skills, 15% preferred, 20% pathway, 10% experience, 10% location).
   - This provides ultra-low latency (<1ms) and avoids a Python sidecar dependency in production, but means `.pkl` artifacts in `models/` are offline reference models.
5. **RAG & GenAI Authenticity (`PARTIAL`):**
   - The Knowledge Copilot is a **sublinear TF-IDF vector space model** across 8 statutory documents, not a fine-tuned deep learning neural embedding model.
   - Recall@1 = 100% is mathematically accurate on the 8 benchmark queries, but represents an in-sample retrieval test.
   - Zero live LLM API calls were made (offline execution).
6. **Agent Security & Permission Boundaries (`PASS`):**
   - Consequential agent actions (`submit_job_application`, `send_recruiter_message`) strictly enforce HMAC-SHA256 signed approval tokens with 15-minute TTL. Autonomous execution attempts are reliably intercepted with `AWAITING_APPROVAL`.
7. **Codebase Health & Reconciliation (`PASS`):**
   - Actual database schema in `apps/api/prisma/schema.prisma` contains **44 models** (reconciling previous claims of 39 models) and **6 enums**.
   - Independent test execution confirmed: **179 API tests passing (14 suites, 0 failures)**, **28 Web tests passing (4 suites, 0 failures)**, Next.js 15 build succeeding (35 static routes), and **100% valid documentation & Mermaid diagrams**.

## 5. Metric and Leakage Audit

### 5.1 The Random Forest Job Matcher ($MAE = 0.030, R^2 = 0.9999$)
The implementation report claimed:
> *"Random Forest Regressor achieved Test MAE of 0.03 points (R² = 0.9999, Spearman rho = 0.9999) compared to Baseline Heuristic MAE of 11.86 points."*

#### Forensic Investigation of `scripts/data_generators/matching.py`
Inspection of the code that generated `job_match_evaluation_ground_truth.json` reveals the exact mathematical formula used to produce `ground_truth_match_score`:
```python
if not is_eligible:
    relevance_grade = 0
    ground_truth_score = 25.0 + mand_ratio * 15.0
elif pathway_match and mand_ratio >= 0.75 and tier_match and location_match:
    relevance_grade = 3
    ground_truth_score = 88.0 + (pref_ratio * 10.0)
elif (pathway_match and mand_ratio >= 0.5) or (mand_ratio >= 0.75):
    relevance_grade = 2
    ground_truth_score = 68.0 + (mand_ratio * 15.0)
elif mand_ratio >= 0.25 or pathway_match:
    relevance_grade = 1
    ground_truth_score = 48.0 + (mand_ratio * 15.0)
else:
    relevance_grade = 0
    ground_truth_score = 32.0
```
And in Notebook 01, the feature matrix $X$ was defined as:
```python
features = [
    'is_eligible',
    'pathway_match',
    'mandatory_skills_ratio',
    'preferred_skills_ratio',
    'firm_tier_match',
    'location_match'
]
```

#### Forensic Verdict on ML-01
- **Target Label Origin:** The target `ground_truth_match_score` is a **noise-free, deterministic piecewise step function of the exact 6 features passed to the model**.
- **Explanation of Metric:** A decision tree ensemble with 100 trees and max depth 5 has more than enough capacity to partition a 6-variable noise-free piecewise function. The $R^2 = 0.9999$ and $MAE = 0.030$ metrics are mathematical artifacts of fitting a tree ensemble to a synthetic piecewise function.
- **Fairness of Comparison:** The "Baseline Static Heuristic" was an arbitrary linear sum formula (`25 + mand_ratio*25 + 25 + 15`), while the target was piecewise nonlinear. The comparison is unfair because the baseline was designed not to match the target generation rule.
- **Real-World Generalizability:** **ZERO**. This model cannot be claimed as an empirically trained predictor of human recruiter hiring preferences. However, it successfully acts as a fast, robust surrogate for the complex CA Career OS matching rule.

### 5.2 Job Fraud Detection ($F1 = 0.970$)
The implementation report claimed:
> *"F1 score = 0.970 with zero false positive flags on legitimate boutique CA practices."*

#### Forensic Investigation of `scripts/data_generators/fraud.py`
- Total samples: $N = 80$.
- Legitimate jobs ($y=0$): 50.
- Review required ($y=1$): 15.
- High-risk scams ($y=1$): 15.
- **Data Duplication & Leakage:**
  - The 15 high-risk scams were generated by taking **only 3 unique templates** (`EY GDS fee scam`, `PwC Telegram deposit scam`, `Deloitte laptop fee scam`) and repeating each 5 times.
  - The 15 review postings were generated by taking **only 3 unique templates** and repeating each 5 times.
  - In Notebook 02, `StratifiedKFold(n_splits=5)` was applied across the 80 rows.
  - **Leakage Event:** Because identical templates were repeated 5 times across 5 folds, identical descriptions and feature vectors existed simultaneously in both the training fold and the test fold.
- **Forensic Verdict on ML-04:**
  - The reported cross-validation $F1 = 0.970$ is inflated by near-duplicate template leakage.
  - However, the underlying linear signals (advance fee requests, Telegram interviews, free email domains for corporate entities, and salary anomalies) are logically sound heuristics. The resulting model works well as a rule-based safety shield, but its true generalization error on in-the-wild novel scams is unknown.

---

### 5.3 Multi-Signal Deduplication ($F1 = 0.909$)
- Total pairs: 100 (25 exact, 35 near-duplicates, 25 same-company-different-role, 15 different-company).
- Baseline exact hash achieved $F1 = 0.588$ because it failed on all 35 near-duplicates where titles were abbreviated.
- TF-IDF Cosine similarity at threshold $\theta = 0.50$ achieved Precision = 1.000, Recall = 0.833, $F1 = 0.909$.
- **Forensic Verdict on ML-05:** Valid for the test distribution. The threshold $\theta = 0.50$ correctly merged cross-posts while keeping distinct openings at the same firm separated.

## 6. RAG, Semantic Retrieval & GenAI Evaluation Audit

### 6.1 Regulatory Knowledge Copilot (GENAI-03 / DL-02)
The implementation report claimed:
> *"Recall@1 = 100%, Recall@3 = 100%, Citation Precision = 100%, 100% Out-of-Corpus Rejection."*

#### Forensic Findings
- **Corpus Size:** Exactly 8 documents (Section 139, Section 143(12), CARO 2020, Ind AS 115, Ind AS 116, Section 44AB, Section 92C, ICAI Ethics).
- **Benchmark Queries:** Exactly 8 queries, each written specifically to query one of the 8 statutory documents.
- **Retrieval Engine:** Sublinear TF-IDF vector space model (`sklearn.feature_extraction.text.TfidfVectorizer`). **It is not a deep learning dense neural embedding model.**
- **Evaluation Validity:** In a toy corpus of 8 documents where each query contains distinctive vocabulary directly matching one document (e.g. `rotation` -> `Section 139`, `Form ADT-4` -> `Section 143(12)`), achieving 100% Recall@1 is trivial.
- **Abstention Gate:** The threshold $\theta = 0.15$ successfully rejected the 3 adversarial out-of-corpus queries (crypto tax, Ind AS 999, stock options). This proves the presence of a functioning abstention gate, but cannot be extrapolated to a full-scale legal RAG system.

## 7. Agentic Behavior & Security Audit

The agentic architecture in `apps/api/src/modules/agent/` was inspected for security controls.

### 7.1 Human-in-the-Loop Consequential Action Gating (`PASS`)
- File: [apps/api/src/modules/agent/approvals.service.ts](../../apps/api/src/modules/agent/approvals.service.ts)
- Consequential tools (`submit_job_application`, `send_recruiter_message`, `book_paid_mentorship`) are marked `PermissionTier.EXPLICITLY_APPROVED_EXTERNAL`.
- **HMAC Token Signing:** When a consequential tool is requested, the system computes:
  $$\text{token} = \text{HMAC-SHA256}(\text{HMAC\_SECRET}, \text{executionId} \mathbin{\Vert} \text{userId} \mathbin{\Vert} \text{toolName} \mathbin{\Vert} \text{paramsHash} \mathbin{\Vert} \text{expiresAtMs})$$
- **TTL Enforcement:** `APPROVAL_TTL_MS = 15 * 60 * 1000` (15 minutes).
- **Tamper Protection:** If tool arguments are altered, `paramsHash` changes and verification fails.
- **Automated Verification:** Verified in `apps/api/test/ml-ai-evidence.test.mjs` (Test 1 & 2 passed).

### 7.2 Tool Input Validation & Tenant Isolation (`PASS`)
- File: [apps/api/src/modules/agent/agent-tools.registry.ts](../../apps/api/src/modules/agent/agent-tools.registry.ts)
- Every registered tool parameter schema is strictly validated via **Zod schemas** (`z.object({...})`).
- Tenant isolation is enforced server-side: tools extract `ctx.userId` and `ctx.workspaceId` directly from the authenticated session context, preventing cross-tenant data access.

### 7.3 Prompt Injection Defense (`PASS` on Tested Patterns)
- Function: `sanitizeJobText(raw: string)` in `apps/api/src/modules/jobs/job-matching.engine.ts`.
- Strips `<script>`, `<style>`, and known jailbreak tokens (`ignore all previous instructions`, `system prompt override`, `<|im_start|>`) by redacting them to `[REDACTED_SUSPICIOUS_TOKEN]`.
- Verified in `apps/api/test/ml-ai-evidence.test.mjs` (Test 6 passed).
- **Security Limitation:** Pattern-based sanitization handles naive text injections, but cannot protect against sophisticated semantic adversarial prompt injections without an LLM guardrail classifier (e.g. Llama Guard).

## 10. Severity-Ranked Findings

### 🔴 HIGH SEVERITY
1. **Finding H-1: Circular Target Definition in Job Match ML Model (`ML-01`)**
   - *Detail:* The ground truth match score in `job_match_evaluation_ground_truth.json` was generated by a deterministic piecewise formula using the exact same 6 features fed to the Random Forest regressor.
   - *Impact:* The reported $MAE = 0.030$ and $R^2 = 0.9999$ are synthetic artifacts, not evidence of real-world CA recruiter preference prediction.
   - *Remediation:* Create an empirical human-annotated dataset from 500+ real hiring outcomes or CA recruiter ratings before advertising machine-learned hiring predictions.

2. **Finding H-2: Near-Duplicate Data Leakage in Fraud Risk Cross-Validation (`ML-04`)**
   - *Detail:* 15 scam postings and 15 review postings were constructed by repeating 3 templates 5 times. Stratified 5-fold CV leaked identical templates across train/test folds, inflating $F1 = 0.970$.
   - *Impact:* The fraud detector's true generalization performance on unseen real-world scam variants is untested.
   - *Remediation:* Deduplicate templates prior to splitting or use GroupKFold grouped by template family.

---

### 🟡 MEDIUM SEVERITY
3. **Finding M-1: Offline Pickles vs Production Code Disconnect (MLOps)**
   - *Detail:* The NestJS backend does not load `.pkl` artifacts from `models/`. It uses hardcoded TypeScript constants manually ported from the notebooks.
   - *Impact:* Model retraining in Jupyter does not automatically deploy to production, creating risk of model-code drift.
   - *Remediation:* Export trained scikit-learn models to ONNX format and execute inference in Node.js using `onnxruntime-node`.

4. **Finding M-2: Overstatement of Deep Learning & RAG Capabilities (`DL-02`, `GENAI-03`)**
   - *Detail:* The RAG and semantic retrieval engines use sublinear TF-IDF vector spaces across 8 documents, not deep learning neural embeddings.
   - *Impact:* Misrepresents lexical TF-IDF as deep learning.
   - *Remediation:* Clearly label the current implementation as an **optimized TF-IDF vector retrieval engine**. Integrate `all-MiniLM-L6-v2` via ONNX or Hugging Face Transformers when dense semantic retrieval is required.

---

### 🟢 LOW SEVERITY
5. **Finding L-1: Inaccurate Database Model Count in Previous Documentation**
   - *Detail:* Previous documentation claimed 39 models, whereas `apps/api/prisma/schema.prisma` actually defines 44 models and 6 enums.
   - *Impact:* Documentation discrepancy.
   - *Remediation:* Updated in this audit report.

## 12. Conclusion

The CA Career OS codebase exhibits **excellent software engineering, architectural discipline, and security hygiene**. All automated test suites (179 backend, 28 web) pass, builds are clean, documentation is in sync, and consequential agent tools are cryptographically protected.

However, from a data science perspective:
- The reported $R^2 = 0.9999$ on the job matcher is a **circular fit of a tree model to a synthetic piecewise function**.
